# SNS・動画は、開発の Harness をそのまま使う（2026-11-09）

## Boss の言葉（要約）

> SNS 用では作らなくて良い。今の開発のハーネスの再利用・別利用として SNS 運用もしていく仕様にする。必要になったタイミングでまた別で作る。その他のものについては一旦消しておいて大丈夫。

やらせたいこと：動画生成、SNS の記事出しなど。

## 決めたこと

- SNS・動画など開発以外の作業も、開発と同じ流れ（Direct が標準・STATUS で引き継ぐ）で進める。専用の部門・役は作らない
- 消したもの：`departments/sns.md`、`rules/sns-standards.md`（sns-writer・sns-poster・sns-reviewer の計画、投稿前の点検の一覧、NG リストの枠）、`rules/limits.md` の投稿数の上限と SNS の緊急停止の欄。中身は git の履歴（この決定の1つ前のコミット）から戻せる
- 残したもの：Approve 区分の「SNS の操作」。AI が投稿・返信・DM などをしようとすると、Guard が Approval Gate を出す

## 使い方の目安

- フォルダ（例：`sns`）を git の管理にし、`.claude/harness.json`（`checks` は空でよい）と `team/` を置く
- 調べ物は Explore、下書きは Orchestrator が直接書く。Worker は Worktree・git が前提の開発向けなので、下書きには使わない
- 投稿は、最初は Boss が手で行う

## 必要になったら考えること

- **ブラウザでの投稿**：Claude in Chrome などのクリック・入力は Guard の対象外。AI にブラウザで投稿させるなら、先に Guard の対応を作る
- **Web を読む役と投稿できる役を分ける**：Web の文章に仕込まれた指示で勝手に投稿されるのを防ぐため（lethal trifecta）。AI に投稿させるときに作る
- **動画生成**：従量課金の API は「お金」で、プロンプトが毎回変わると1本ごとに確認画面が出る。中身をファイルから読む決まった形のスクリプトにすれば、まとめての許可が効く。あわせて、月の予算（`rules/limits.md`）と、動画の置き場所（git の外）を決める
- 投稿先の SNS・使う生成サービス・月の予算の目安
